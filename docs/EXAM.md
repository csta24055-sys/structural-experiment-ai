# 試験出題予測・集中対策システム（structlab-exam）

授業動画・配布資料・課題・過去問・Box 共有リンクを読み、**出題根拠のある論点だけ**を S/A/B/C に分けて、
対策教材と模擬テスト 3 回分を作ります。外部 AI（有料 API）は使いません（規則ベースと無料のローカル処理のみ）。

## 使い方

```bash
pip install -r requirements.txt && pip install -e .
structlab-exam env                                   # 使える外部ツール（ffmpeg・OCR・Playwright など）
structlab-exam run --input 資料フォルダ                # ローカルの資料から教材を作る
structlab-exam run --dropbox-root /授業動画 --dropbox-out /試験対策出力   # Dropbox から
structlab-exam run --input 資料 --box-url https://xxx.app.box.com/s/...  # Box 共有 URL を直接指定
structlab-exam box-check 第04回.url                   # Box 共有リンクだけを検査
```

資料フォルダの置き方（科目名のフォルダに入れると確実に分類されます）:

```
資料/
  環境工学Ⅳ/
    第03回_講義資料.pdf      … スライド（PDF・PowerPoint・Word）
    第03回_授業動画.mp4      … 授業動画
    第03回_授業動画.vtt      … 字幕・文字起こし（動画と同じ名前。あれば音声の代わりに使う）
    授業動画/第04回.url      … Box 共有リンク
    過去問/2024年度_期末試験.pdf
    課題_第3回.pdf
    試験範囲のお知らせ.txt
```

ファイル名に「過去問」「課題」「演習」「小テスト」「試験範囲」「解答」を含めると役割が判定されます。
科目の一覧（別表記・専門用語・教員名）は `configs/exam.yaml` の `subjects` に書けます。空でも動きます。

## 出力（output/exam、または Dropbox の出力フォルダ/試験対策システム）

```
科目一覧/<科目>/試験対策/
  最重要事項.pdf / 徹底対策資料.pdf / 公式一覧.pdf
  予想問題.pdf / 解答用紙.pdf / 解答解説.pdf     （Word 版 .docx も）
  判定一覧.pdf        … 全論点の S/A/B/C と理由（B・C は題名と理由だけ）
  出題根拠.json       … 根拠台帳（支持・反対証拠、明示/推測、未確認事項、出典）
  模擬テスト第1〜3回/ 問題.pdf・解答用紙.pdf・解答解説.pdf
  品質検査.json       … PDF/Word の検査結果（文字化け・空ページ・ページ番号）
科目一覧/<科目>/解析データ/ スライド照合.json・重要発言.json
Boxリンク管理/ URL一覧.json・アクセス検査結果.json・動画取得可否一覧.csv・抽出ログ.json
未分類・要確認/一覧.json
全体処理履歴/ 分類結果.json・実行報告.json
```

判定の履歴（A→S など）は `work/exam/history.jsonl` に追記されます。

## 判定（S/A/B/C）

| 判定 | 意味 |
|---|---|
| S | 教員が出題を明示（「試験に出します」「毎年出ます」「この問題が解ければ大丈夫」）。後の授業で取り消されていないもの |
| A | 過去問との一致・暗記/計算の指示・課題・反復などの根拠の合計が基準以上 |
| B | 根拠はあるが不足。**未解析の資料があり判断できない論点（B-要確認）もここ** |
| C-除外 | 出題しないと明示・告知された試験範囲の外 |
| C-低 | 解析済みの資料の範囲で根拠が見つからない |

- 点数は根拠ごとの内部点数で、**出題確率ではありません**（％は表示しません）。重みは `configs/exam.yaml` の `scoring`。
- 教員の発言パターン（出題・暗記・除外・訂正など）も `configs/exam.yaml` の `cues` にあり、コードから分離しています。
- 「試験範囲内」であることは出題確定ではありません（支持証拠として記録するだけ）。
- 手動修正: `--overrides 修正.yaml`（`論点の題名: {grade: A, reason: 先生がプリントで指示}`）。自動判定も残ります。

## Box 共有リンクの扱い

Dropbox に Box の共有リンク（.url）しか無い場合、リンクを検査して次の状態に分けます。

| 状態 | 意味 | 解析 |
|---|---|---|
| A | 公式の手段で動画本体を取得できた | 映像・音声を解析する |
| B | ページで再生できるが、**共有設定でダウンロードが許可されていない** | 未解析（推測で根拠を作らない） |
| C | ファイル名などのメタデータだけ確認できた | 未解析 |
| D | ログイン・パスワードが必要 | 未解析 |
| E | リンク切れ・期限切れ・ネットワーク制限・タイムアウト | 未解析 |
| F | 取得したが壊れている・形式に未対応 | 未解析 |

- 共有ページは JavaScript で描画されるため、Playwright（Python 版、無ければ Node 版）の Chromium で開きます。
  `networkidle` は動画プレーヤーの通信で終わらないことがあるので使わず、本文・再生時間が表示されるまで待ちます。
- `BOX_ACCESS_TOKEN` があれば Box 公式 API（`GET /shared_items`）で権限を確認します。大学の共有リンクは、
  個人の Box アカウントのトークンでは参照できないことがあります（その場合は API の結果を「見つからない」と記録）。
- 取得は `--allow-download` を付け、かつ Box がダウンロードを許可している場合だけ（公式 API か、ページの
  ダウンロードボタンによる通常の操作）。**ダウンロード禁止・認証・DRM を回避する処理（再生用の通信の横取りなど）は実装していません。**
- 取得できない動画は「未解析」として教材の冒頭と判定一覧に表示され、その講義回の論点は C になりません。
  代わりに、教員から動画ファイルや字幕の提供を受けて `<動画名>.vtt` を置けば、発言の解析に使えます。

## GitHub Actions

| ワークフロー | 内容 |
|---|---|
| Tests | push・PR ごとに pytest（合成データのみ） |
| Exam preparation | 手動実行。Dropbox の資料から教材を作り、Dropbox の出力フォルダに保存。処理状態も Dropbox に保存し次回は続きから |
| Box link check | 手動実行。Dropbox 上の .url の Box リンクを検査 |

**このリポジトリは公開されています。** 公開リポジトリの Actions のログ・Artifacts・キャッシュは第三者が見られる
場合があるため、授業内容を含む教材と処理状態は Dropbox にだけ保存し、ログには件数だけを出します（`--quiet`）。
リポジトリを非公開にした場合だけ、教材を Artifacts（7 日で削除）にも保存します。

Secrets（Settings → Secrets and variables → Actions）:

| 名前 | 用途 |
|---|---|
| DROPBOX_APP_KEY / DROPBOX_APP_SECRET / DROPBOX_REFRESH_TOKEN | 資料の読み取り・出力フォルダへの保存（`files.content.write` が必要） |
| BOX_ACCESS_TOKEN（任意） | Box 公式 API での確認・許可された取得 |

## 制限（未実装・未検証）

- 問題は資料の文と式から規則で作ります。資料に無い応用問題や、採点基準の正確な再現はできません（記述の採点基準は「推定」と表示）。
- 計算問題の数値はシステムが設定した例題の値です。式は sympy で解いて検算しますが、PDF の文字だけでは
  「bh2」が bh² か添字か区別できないため、そのような式からは計算問題を作りません（公式一覧には載せます）。
- 画面の文字（OCR）は tesseract が必要です（GitHub Actions では導入済み）。手書き・数式画像の読み取り精度は検証していません。
- 音声の文字起こしは faster-whisper（無料・ローカル）を選んだときだけ行います。既定は無効で、その場合の動画音声は「未解析」になります。
- 実際の試験問題による的中率の検証（バックテスト）は、試験問題が手元に無いため未実施です。
