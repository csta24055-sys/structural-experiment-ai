# 費用最適化（M25）: 3大原則・保存の効率化・さらなる削減

M24（`docs/OPTIMIZATION_M24.md`）の続き。要求事項は台帳の P136〜P142。
3大原則: ①得られる成果を減らさない ②品質を下げない ③今の方式に固執しない（①②を検証できれば作り替えてよい）。
記号: [実測] [計算]（公式料金×実測量）[推定]（仮定を含む）。金額は Batch 込み・1 USD = 155 円・mid。

## 1. 全体設計の方針（根本的に異なる 4 案）と内部の個別最適化

| 全体設計 | 考え方 | 内部の個別最適化 | 状態 |
|---|---|---|---|
| G1 送り方の最適化（今の構成のまま） | 依頼の内容は変えず、料金の扱い・送る順序だけを最適化 | Batch、まとめ送り、キャッシュの先書き、中断の再開、依頼の指紋による再利用（M24） | **採用済み**（内容が同じことを検証済み） |
| G2 共通部分の先頭化（入力の再利用） | 資料全体の理解・指示文を依頼の先頭に置き、数百件で使い回す | C1v（照合）、C1r（再解釈）、C4（照合のまとめ） | 候補（比較の承認待ち） |
| G3 差分の出力（出力の再利用） | 出力は入力の 5 倍の単価。繰り返しの工程で「変わらない部分を書き直させない」 | **C5（再解釈は変わった項目だけ返す）**: 今は変更がなくても場面の解釈の全体（約 1,500 トークン）を書き直している。今後の候補: 全体の理解の更新も差分に | C5 を実装（既定は無効） |
| G4 画面の差分入力（画像の再利用） | 画面録画は前の画面との差分が情報。変わらない部分を拡大し直さない | D1（Excel の「変化した画面の全体」を 2 倍でなく元の解像度に。変わった部分の 3 倍の拡大は残す）。Excel の画像の 70% がこの全体画面 | 設定を実装（`reading.roles[].event_scale`、既定は無効）。M21 の最高品質の指示との兼ね合いで利用者の判断 |

組み合わせ: G1 はすべてと両立。G2 と G3 は同じ段階（再解釈）で重なる（先頭の理解はキャッシュ、出力は差分）。
G2+G3 を「再解釈から先」の 1 回の比較でまとめて確かめると比較の費用が最も小さい（下表）。

## 2. 費用（全 9 資料、円）

費用モデルの修正: 再解釈の出力を「変更点だけ」と仮定していたが、今の指示は変更がなくても解釈の全体を返させているため、
出力を「場面の理解と同じ量＋変更点」に直した（最適化前・後の両方に同じ修正）。

| | low | mid | high |
|---|---|---|---|
| 最適化前（M24 開始時点の構成） | 約 10,230 | 約 18,383 | 約 31,180 |
| 現在の既定（G1 を採用） | 約 9,790 | **約 17,704**（−679、−3.7%） | 約 30,510 |
| 候補 C1+C4+C5 が比較で採用された場合 | 約 9,000 | 約 14,639（−3,744、−20.4%） | 約 23,280 |
| さらに D1 も採用された場合 | — | 約 13,860（−24.6%） [推定] | — |

内訳（mid、現在の既定）: 読み取り 7,086（うち Excel 約 4,400）＋理解・統合 10,618。
読み取りの入力は実測（全 9 資料 8,955,399 トークン）、出力・キャッシュの当たり方は仮定。
**Excel・レポートの作成・修正・検証・書き出し**は未実装（作成は承認まで行わない指示）のため費用は未算定。
再実行・中断からの復旧は、依頼の指紋・Batch の再開・DB の持ち越しで「同じ依頼は 0 円」。

## 5. 保存・引き継ぎの効率化（P137・P138）
| 方法 | 以前（M24） | 今後 |
|---|---|---|
| コード・設定・ワークフロー・依存関係 | `git archive` で機械的に保存（AI の作業なし） | 同じ |
| モジュール・設定・テスト・環境・要求事項の一覧 | スクリプトで自動生成 | 同じ |
| コードから分からない前提・判断理由・進捗 | 保存のたびに AI が引き継ぎ資料を書き下ろし（約 38 KB） | `docs/handoff/` に置き、**変わった部分だけ直す**（今回の変更 約 3 KB） |
| 最適化前後の比較 | AI が比較資料を書いた | `scripts/snapshot.py --compare` で機械的に作り、結論だけを短く書く |
| 検証 | アーカイブを展開してテスト | 同じ（自動。約 6〜10 分） |
保存の費用: 有料 API 0 円、Actions 0 分。ストレージは保存 1 回 約 0.5 MB（リポジトリ内）。AI の作業は文章の差分だけ。

## 6. さらに削減できる可能性
- G3 の拡張: 全体の理解の更新（再解釈の後）を差分にする（出力 約 5,000 トークン×更新回数）。照合の出力も同様
- G4 の拡張: 変化が小さい画面（セル 1 つの入力など）は全体画面を送らず、変化部分の拡大と直前の画面への参照にする（要比較）
- 読み取りの AI を 1 つのジョブにまとめ、Actions の待ち時間を減らす
- 有料実行の `cache_read_tokens` で先書きの効果を実測し、閾値を合わせる
