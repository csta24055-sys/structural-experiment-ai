## 意味理解層（追加改修）の確認状況

前提: 実際の Dropbox・Claude API・実際の講義動画は使っていません。AI の部分は **模擬AI（MockProvider）** による確認です。
模擬AIは決められた規則で応答するだけなので、「多段階の処理が正しくつながり、検証の仕組みが働くか」は確認できますが、
**「動画の意味を正しく理解できるか」「指示を漏れなく抽出できるか」は確認できていません。**

### 実装済み・自動テストで確認済み（tests/test_semantic.py、40件）

| 項目 | 確認内容 |
|---|---|
| 言い回しによる指示の8分類 | 禁止・非推奨・必須・要望・推奨・任意・条件付き（条件と条件内の強さ）・その他を書き言葉13文・話し言葉5文で確認。「Aして、Bしないで」の2指示への分割、「訂正します。」を次の文の指示に引き継ぐこと、「ただし」の検出 |
| 指示の根拠の記録 | 全指示に資料名・時刻（動画）またはページ・根拠の発言・前後の文脈・発話時の画面。指示1件の全項目（16項目＋照合・有効性）が JSON に出ること |
| 局所理解の入力 | 時刻付きの発話と時刻ラベル付きのフレーム画像を同時に渡し、直前の場面の理解・直後の場面の発話を添えること |
| 3段階の順序 | 局所理解 → 全体理解 → 再解釈 → 指示抽出 → 照合 の順に実行されること。再解釈・指示抽出に全体理解が渡されること |
| 相互照合ループ | 後半の訂正を受けて前半の場面の解釈が修正され（変更前後・理由を保存）、全体理解が版2に更新され、2回目で変更なし＝収束と記録されること |
| 見落としの検出 | AIがわざと拾わなかった指示を、規則候補との突き合わせで見落とし候補にし、第3回で元の発話と照合して採用すること |
| 分類ミスの検出 | AIがわざと逆向きに分類した禁止事項を、原文の言い回しとの比較で検出し、原文に基づいて修正すること。修正案が原文と逆向きなら採用せず「未解決」に残すこと |
| 照合時の再解析 | 曖昧な指示の前後を広げ、元動画から画面を取り直し、区間をまたいで音声を再文字起こししてAIに渡すこと |
| 訂正・例外・矛盾 | 明示的な訂正だけ前の指示を無効にすること、AIだけが主張する訂正は無効にしないこと、向きが逆の指示を未解決の矛盾として記録しどちらも採用しないこと、例外を前の指示に関連付けること |
| 資料横断 | 動画とPDFの間の矛盾（触らないで⇔触ってもよい、PDF⇔Wordで提出）と共通の指示を検出、統合理解を資料単位と別に保存、AIが存在しない指示番号を挙げた場合の除外 |
| 網羅率 | 処理した時間（ページ）の割合を段階別に算出し、未処理の時間帯を列挙。解析に失敗した区間（20〜40秒）を隠さず網羅率60%・失敗箇所に記録。文字起こしなしの音声を0%と表示。網羅率と指示の検出率を混同しない注記 |
| 再開・重複防止・上限 | 2回目の実行でAIを呼ばないこと、AI使用量の上限で止まっても次回続きから（同じ場面を2回解析しない） |
| 有料解析の承認 | 許可なしでは外部AIを呼ばないこと、`estimate` がAPIを呼ばずに呼び出し回数・概算費用を出すこと |
| 長い資料 | 全体理解の入力が長い場合に、切り捨てずに分割して統合すること |
| 出力スキーマ | 6種類のスキーマが JSON Schema として妥当で、構造化出力の前提（全項目必須・追加項目禁止）を満たすこと |
| 既存機能 | 前回の70件のテストがすべて成功（合計110件） |

### 実資料・実APIでの検証待ち

| 項目 | 内容 |
|---|---|
| **AIによる意味理解の質** | 場面の意味・目的・前後関係の理解、全体理解（流れ・論理構造・結論）、訂正や条件変更の把握、説明を見ていない人に伝わる説明文になるか |
| **指示の抽出の網羅性・分類の正確さ** | 実際の先生の話し方（言いよどみ・省略・遠回しな表現）での抽出漏れ・分類ミス。規則は代表的な話し言葉にも対応したが、実際の講義の言い回しで取りこぼす可能性がある |
| 実際の Claude API | 6種類の出力スキーマが実APIで受理されるか、応答時間、トークン量、実際の費用（`estimate` は目安） |
| 日本語の講義音声の文字起こし | 意味理解の前提。精度が低いと根拠の照合も働かない |
| 話者の区別 | 先生と学生の発言を区別していない |
| 規則の関連付けの精度 | 訂正・例外・矛盾の対象の特定は内容語の一致による目安。実資料で誤った関連付けが起きる可能性がある |
| 大量の資料での処理時間 | 数時間分の動画・多数の資料での AI 呼び出し回数・時間 |

## 未検証（実際の資料・認証情報がそろうまで確認できないもの）

| 項目 | 理由・確認方法 |
|---|---|
| **実際の Dropbox API との通信**（認証、一覧、rev 指定ダウンロード、出力フォルダへのアップロード、レート制限時の再試行） | アプリキー・トークン未設定のため。Dropbox コネクタ経由で `/鋼材実験レポート用` フォルダが存在することだけ確認済み。設定後に `structlab check` → `structlab scan` で確認 |
| **実際の Claude API 呼び出し**（構造化出力スキーマが受理されるか、画像付きリクエスト、server-side fallbacks、トークン使用量） | APIキー未設定のため。最初は `ai.max_calls_per_run: 5` などで少量から確認することを推奨 |
| 解析の**品質** | 日本語の講義音声の文字起こし精度、先生の指示の読み取り、Excel 操作画面（セル番地・メニュー）の読み取り、手書きの板書、画像化された数式、複雑な表の検出精度。実資料で結果を目視確認する必要あり |
| 話者の区別 | 話者識別は行っていない。音声の発言はすべて「音声での発言」として扱い、先生かどうかは区別しない（AIが文脈から判断した場合も、根拠の発言を併記） |
| 区間の境目の発話 | 動画を区間に分けて文字起こしするため、境目をまたぐ発話が分断される可能性がある |
| 数GB級の実動画・数千ファイル規模 | 処理時間・ディスク使用量は未計測。CPU での文字起こしは動画の長さと同程度以上の時間がかかる見込み |
| GitHub Actions の `analyze.yml` | Secrets 未設定のため未実行 |
| iPhone からの操作 | Claude アプリ・GitHub アプリからの起動手順はドキュメント化のみ |
| `dropbox-auth`（トークン取得） | 実際の Dropbox アプリでのコード交換は未実行 |
| .docx・PowerPoint の画像や数式（OMML） | 最小構成の pptx の本文のみ確認 |
| Windows / macOS での実行 | Linux のみ確認（`fcntl` を使うため Windows では動かない） |
