# 動作確認済みの範囲と未検証の項目

確認日: 2026-10-20 / 環境: Claude Code on the web のクラウドコンテナ（Linux, Python 3.13, ffmpeg 6.1, tesseract 日本語, faster-whisper）
実際の実験資料は使っていません。すべて自動生成したダミーの PDF・動画・画像・Excel・ZIP で確認しています（`tests/`）。

## 動作確認済み（自動テストで確認）

| 項目 | 確認内容 | テスト |
|---|---|---|
| 再帰的な一覧取得 | ローカルフォルダの再帰走査。Dropbox は**模擬クライアント**で `list_folder(recursive)` → `list_folder/continue` のページング処理、フォルダ除外、相対パス化 | test_config_and_integrations |
| 大容量の分割処理 | 96MB のダウンロードを1MBずつ受信しながらハッシュ照合（ピークメモリ 24MB 未満。192MB でも約9MB）、スパースファイルのハッシュ計算、153ページPDFをページ単位、1,200行のExcelを500行単位、5分の動画を60秒区間に分割 | test_large_files |
| 途中停止と再開 | STOP ファイル・最大実行時間での安全な停止、異常終了（処理中のまま残った状態）からの回復、完了済み単位を再処理しないこと（attempts=1 のまま）、**使い捨て環境間の再開**（state.db を出力先へ保存→空の別環境で取得して続行。出力先は模擬） | test_resume_and_detection, test_cli_and_sync |
| 新規ファイルの検出 | 1回目の後に追加したファイルだけを2回目で処理 | test_resume_and_detection |
| 重複処理の防止 | 2回目の実行で単位・AI呼び出し・結果件数が変わらない。内容が同一のコピーは `duplicate` として解析しない | test_resume_and_detection |
| 更新・削除 | 上書きされたファイルを新しい版として再解析し古い版の結果を出力から除外、削除されたファイルを除外 | test_resume_and_detection |
| アップロード途中の除外 | 更新直後のファイルは待機し、時間経過後に解析対象、`~$*.xlsx`・`*.part` を無視、スキャン後に書き換わったファイルを検出して待機に戻す、ダウンロード内容のハッシュ不一致を検出 | test_resume_and_detection, test_large_files |
| 読み込み失敗時の復旧 | 壊れたPDF・途中で切れた動画を失敗として記録（再試行上限まで）、一時的な抽出エラー・AIエラーを次回自動再試行、AI使用量上限で残りを次回に持ち越し、`retry` コマンド | test_recovery, test_video |
| 動画の音声と映像の対応付け | スライド3枚の動画＋模擬文字起こしで、17秒の発話が15秒から表示される画面（`=AVERAGE(B2:B10)`）に対応すること、重要語による重要場面の検出と追加解析、発話項目に時刻が付くこと、音声のみのファイル | test_video |
| 実音声の文字起こし | 合成音声（espeak-ng, 英語）入りの動画を faster-whisper（tiny）で文字起こしし、時刻付きでタイムラインに入ること（精度は未評価。tiny は単語を誤認識した） | test_video（slow） |
| 解析結果の出典管理 | すべての項目にファイル名、PDFはページ、動画は時刻。ZIP内は `ZIP名!/内部パス`。10分類すべての見出し、一覧（フォルダ・容量・更新日時・形式） | test_provenance_and_report |
| 先生の指示とAI推測の区別 | AIの推測は先生の指示にならない、根拠が原文に無い指示は確定しない、スキーマ外の出力の破棄、区間外の時刻の不採用、読み取り不能の記録 | test_provenance_and_report |
| 矛盾の検出 | 2つの資料で提出期限が 11月20日 / 11月27日 と異なることを検出 | test_provenance_and_report |
| PDF | 本文、表（罫線表）、数式候補（σ = P / A 等）、ベクター図形の数、スキャンページの判定とページ画像化 | test_formats |
| Excel | シート構造、数式（同型数式のまとめ）、キャッシュ値、散布図・軸タイトル・系列参照・近似曲線、マクロ有無 | test_formats |
| 画像 | PNG・HEIC、寸法、OCR、AIへの画像受け渡し | test_formats |

## 未検証（実際の資料・認証情報がそろうまで確認できないもの）

| 項目 | 理由・確認方法 |
|---|---|
| **実際の Dropbox API との通信**（認証、一覧、rev 指定ダウンロード、出力フォルダへのアップロード、レート制限時の再試行） | アプリキー・トークン未設定のため。Dropbox コネクタ経由で `/鋼材実験レポート用` フォルダが存在することだけ確認済み。設定後に `structlab check` → `structlab scan` で確認 |
| **実際の Claude API 呼び出し**（構造化出力スキーマが受理されるか、画像付きリクエスト、server-side fallbacks、トークン使用量） | APIキー未設定のため。最初は `ai.max_calls_per_run: 5` などで少量から確認することを推奨 |
| 解析の**品質** | 日本語の講義音声の文字起こし精度、先生の指示の読み取り、Excel 操作画面（セル番地・メニュー）の読み取り、手書きの板書、画像化された数式、複雑な表の検出精度。実資料で結果を目視確認する必要あり |
| 話者の区別 | 話者識別は行っていない。音声の発言はすべて「音声での発言」として扱い、先生かどうかは区別しない（AIが文脈から判断した場合も、根拠の発言を併記） |
| 区間の境目の発話 | 動画を区間に分けて文字起こしするため、境目をまたぐ発話が分断される可能性がある |
| 数GB級の実動画・数千ファイル規模 | 処理時間・ディスク使用量は未計測。CPU での文字起こしは動画の長さと同程度以上の時間がかかる見込み |
| GitHub Actions の `analyze.yml` | Secrets 未設定のため未実行 |
| iPhone からの操作 | Claude アプリ・GitHub アプリからの起動手順はドキュメント化のみ |
| `dropbox-auth`（トークン取得） | 実際の Dropbox アプリでのコード交換は未実行 |
| .docx・PowerPoint の画像や数式（OMML） | 最小構成の pptx の本文のみ確認 |
| Windows / macOS での実行 | Linux のみ確認（`fcntl` を使うため Windows では動かない） |
