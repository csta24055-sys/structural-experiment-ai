# チェックの全体設計（要件 → 工程 → 項目）

システム全体として必要な検証を「検証要件」（R1〜R15）として先に定め、それぞれを最も適した工程のチェック項目に割り当てています。
既存の検証（前回までに実装していたもの）も同じ一覧に含めて整理しました。各工程のチェックを合わせると、全要件がどこかの工程で担当されます。

- 一覧の定義: `src/structlab/checks/catalog.py`（項目ID・工程・要件・方法・実施方法・既存/今回）
- 実行結果: `results/checks/catalog.md`（要件×工程の対応表と、項目ごとの最新の結果）、`results/checks/checks.md`（成功以外の明細）
- 一覧と実装の一致は自動テスト（`tests/test_check_catalog.py`）で保証:
  記録されたチェックはすべて一覧に登録されている／状況に依存しない項目は必ず記録される／
  「仕組みで保証」の項目が挙げるテストが実在する／全要件に担当の項目がある

処理の順序（取得 → 抽出 → 意味理解 → 指示抽出 → 照合 → 統合）と3段階解析は変えていません。
既存の検証は再実行せず、その結果を記録しています（同じ検査を二重に行わない）。

## 状態の区別
成功（照合して一致）／不一致（照合して食い違い）／要確認（機械的に判断できない疑い）／未検証（照合の材料・手段がない。**成功ではない**）／チェック不能

## 検証要件
| 要件 | 内容 |
|---|---|
| R1 | 資料を全件・最新版・改変なしで取得し、アップロード途中の物を使わない |
| R2 | 危険なファイル・上限を超えるファイルを安全に扱う |
| R3 | 資料の内容（全ページ・全区間・全セル、文字・数値・数式・表・グラフ）を漏れなく正確に読み取る |
| R4 | 音声と映像を時刻で正しく対応付ける |
| R5 | 場面ごとの解釈が原文に根拠を持ち、前後の説明と整合する |
| R6 | 資料全体の解釈が場面の解釈と整合し、訂正・補足・例外・条件変更・矛盾を反映する |
| R7 | 指示を漏れなく、正しい分類・条件・発言者・対象・根拠で記録する |
| R8 | 指示同士の関係（訂正・例外・繰り返し・矛盾）を、根拠なく決めつけずに扱う |
| R9 | 複数の資料の間で、数値・提出条件・指示・作業手順の一致と矛盾を確認する |
| R10 | 数値・数式・計算を再現できる |
| R11 | 提出物が資料・計算・指示・提出条件と一致する（将来の工程） |
| R12 | 文章スタイルの調整で内容が変わらず、スタイルは最終工程だけに使う |
| R13 | 最初の結論に依存しない独立した確認ができる |
| R14 | 処理と解析の網羅状況・失敗・未処理・上限を隠さず示す |
| R15 | 元資料を書き換えず、外部送信は許可時のみ、秘密情報・個人情報を保存しない |

## 工程ごとの担当（項目ID）
| 工程 | 担当する検証 | 項目 |
|---|---|---|
| 資料の取得 | 全件列挙、アップロード途中の除外、取得内容の照合、最新版、一時ファイルの除外、重複、ZIPの安全性、上限、対応形式、ファイル単位の処理結果 | A1〜A10 |
| 資料抽出 | 読み取り失敗、分割の網羅（全ページ・全時間・全行）、音声と映像の時刻対応、文字起こし、画面の取得、OCR、数値の誤読、数式の構文、表の構造、Excelの再計算・セル明細・上限・グラフ参照、AIでしか読めない内容、単位ごとのAI抽出の根拠 | B1〜B15 |
| 局所理解・全体理解 | 意味理解の実施、場面の解釈の根拠、前後の関係、読み取り不能、全体理解の参照、訂正等の根拠、訂正の把握の一致、相互照合の収束、全体理解の欠落、一見矛盾する説明、全場面の位置付け | C1〜C11 |
| 指示抽出 | 分類と言い回し、根拠の引用、時刻、条件、発言者、対象作業、見落とし候補、推論の区別、照合の上限、訂正・例外等の関係先、資料内の矛盾 | D1〜D11 |
| 複数資料の統合 | 資料間の数値（Excelの定数を含む）、提出条件、指示の矛盾、共通の指示、作業手順の根拠、統合の対象の網羅 | E1〜E6 |
| 提出物（将来） | 再計算、単位、グラフの種類・近似曲線・凡例・軸タイトル、数値の出典、必要な章、考察、提出条件、指示の遵守 | F1〜F11 |
| 文章スタイル（最終工程） | 内容の保存、適用する項目の範囲、最終工程だけで使う、適用前の保存 | G1〜G4 |
| 独立した再検証 | 指示の独立した再抽出、数値・数式の独立した再計算（B10・E1が担当し重複させない） | H1〜H2 |
| 運用・全体 | 処理の網羅、解析網羅率、AI使用量の上限、外部送信の許可、元資料の保護、秘密情報、個人情報（文章スタイルPDF）、再開・重複処理の防止 | O1〜O8 |

### 実施方法
- **実行時に記録**: 実行のたびに結果を記録（多くは該当する状況のときだけ。例: Excel があるとき、AIを使ったとき）
- **仕組みで保証**: コードや設定の検証で常に保証し、自動テストで確認（例: 元資料に書き込む処理が無い、設定ファイルにAPIキーを書くと停止、スタイルのコードを解析側が参照しない）
- **提出物・最終工程で実行**: 下書き・確定稿を渡したときに実行（今は提出物を作らない）

## 主なチェックの補足
- **Excelの再計算**: 保存値を使わず、入力値から数式を計算し直す（参照先の数式も計算し直す）。対応していない関数・日付は「未検証」
- **発言者**: 話者識別をしていないので、音声の指示は「発言者未確認」。利用者が確認した場合だけ「先生（確認済み）」。AIの推論には発言者を付けない
- **独立した再検証**（`structlab reverify`）: 最初の結論・全体理解を見せずに、元の範囲だけから規則（無料）とAI（許可時のみ）で指示を取り出し直して突き合わせる。食い違いは修正案として保存し、自動では書き換えない
- **解析網羅率**: 処理した時間・単位の割合。指示の検出率ではない

## コマンド
```bash
structlab checks                       # 工程別の集計、checks.md と catalog.md の生成
structlab reverify                     # 独立した再検証（規則のみ・無料）
structlab reverify --allow-external-ai # AIによる盲検の再抽出も行う（有料。事前に承認を得ること）
structlab check-draft 下書き.md --format PDF
structlab check-draft 下書き.xlsx
```
