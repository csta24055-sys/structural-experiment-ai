# G5: Claude Code（定額の契約）で AI の解析を行う手順

**目的**: 従量課金の API（本番 1 回 約 17,700 円）の代わりに、利用者が既に支払っている Claude の定額の契約（Pro / Max）の
Claude Code で同じ依頼を処理し、実際の支払いを減らす。依頼の内容は API と同じものをファイルで受け渡す。
**既定では使わない**。本番に使うには (1) 利用者の承認、(2) 見本の比較 P-G5（API 約 790 円）の合格が必要。
公式の利用条件との関係・同等性の確認・費用は `docs/OPTIMIZATION_M27.md`。

## 1. 仕組み（AI はすべて Claude Code の会話の中で動き、外部のプログラムから Claude を呼ばない）
| 役割 | 何をするか | 実体 |
|---|---|---|
| 実行役（無料の計算） | 依頼を作る・答えを検査して取り込む・進捗と完了の判定 | `scripts/g5_driver.py`（AI を呼ばない。有料 API の鍵を子の処理に渡さない） |
| 答え役（定額の利用枠） | 依頼 1 件を読み、出力の形に合う答えを書く | Claude Code のサブエージェント `.claude/agents/g5-answerer.md`（新しい文脈・Read と Write だけ・モデル claude-opus-5-5・effort high） |
| 進行役（定額の利用枠） | 実行役を動かし、答え役を起動し、利用枠と追加課金を確認する | 利用者が始めた Claude Code のセッション（このリポジトリの Claude） |

依頼のファイル（`work/g5/queue/`）: `requests/<指紋>.json`（指示・本文・出力の形・API と同じ画像の PNG と、長辺 2000 を超える画像の部分画像）、
`inbox/`（答え役が書く）、`answers/`（検査に合格した答え）、`rejected/`（形の違う・壊れた・重複した答えと理由）、`log.jsonl`。

## 2. 承認後の操作（利用者がすること）
1. **Claude の追加利用（usage credits / extra usage）を無効にするか、月の上限を設定**（設定 → 使用量。https://support.claude.com/en/articles/12429409）。
   有効のままだと、利用枠を超えた分が課金される可能性がある
2. P-G5 を行う場合だけ: Claude Code のクラウド環境の設定（セッションの題名の横の環境メニュー → 編集）に、API の鍵を
   `ANTHROPIC_API_KEY` という名前で登録（チャットには貼らない）。新しいセッションから使える
3. Claude Code で「G5 を開始して」と伝える。その後は利用枠の上限で止まったときに「続けて」と伝える（上限は 5 時間ごとに回復。
   週の上限に達した場合は回復の日時まで待つ）

## 3. 進行役（Claude）の手順（1 周）
1. `python3 scripts/g5_driver.py step`（取り込み → 次の依頼の作成。読み取りが全部そろうまで理解・統合に進まない）
2. 追加課金の確認: セッションの情報（get_session）の `rate_limit_info.isUsingOverage` が true なら**直ちに止めて利用者に知らせる**
3. `python3 scripts/g5_driver.py next -n <同時に起動する数>` で未回答の依頼を受け取り、1 件ごとに g5-answerer を起動
   （依頼ファイルの場所だけを渡す。同時の起動は 10 件程度まで。公式の上限は 20）
4. 1 に戻る。`status` の `complete` が true になったら終わり（テスト用の仮の答えが 1 件でもあれば完了にしない）
5. 利用枠の上限に達したら、そのまま止める（Claude Code は回復まで止まり、モデルを勝手に変えない。公式）。
   答え役が途中で止まった依頼は、受け渡し中の印（2 時間）が切れた後に再び渡す。書きかけの答えは検査で落とす

## 4. 答え方の決まり（g5-answerer に書いてある内容）
- 1 件ごとに新しい答え役（前の依頼の内容を持ち込まない）。依頼ファイルと、その中の画像以外は開かない
- 画像はすべて Read で開き、部分画像（tiles）があれば必ず開く（Read は長辺 2000 を超える画像を縮小するため。2026-10-22 に確認）
- `system` を指示、`text` を資料として扱い、出力の形（JSON スキーマ）に合う JSON だけを `inbox/<id>.json` に書く
- 推測で埋めない。読めないものは出力の形の「読めない・不確か」の欄へ

## 5. 現実の制限
- 依頼 約 1,500 件（読み取り 約 630＋理解・統合 約 890）。理解・統合は場面の順に 1 件ずつ進む工程があり、最も長い資料で 約 100 周
- 利用枠: 5 時間ごと・週ごとの上限（プランによる。数値は公式に非公開）。大量の並列は週の上限を早く使い切る（公式の注意）
- 所要時間: 数十時間〜数日（利用枠の回復待ちを含む）。利用者の操作は、上限で止まったときの「続けて」（1 日に数回程度）
- 公式に閾値の無い「通常の個人の利用」の範囲の判断は Anthropic にある（未確認）。1 つの会話の中で、利用者の指示で、利用者自身の資料を処理する
