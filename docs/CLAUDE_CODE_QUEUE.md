# 候補 G5: Claude Code（定額の契約）で AI の解析を行う手順

**目的**: 従量課金の API（本番 1 回 約 17,700 円）の代わりに、利用者が既に支払っている Claude の定額の契約（Claude Code）で
同じ依頼を処理し、実際の支払いを減らす。依頼の内容（指示文・本文・画像・出力の形）は API と同じものをファイルで受け渡す。
**既定では使わない**。使うには (1) 利用者の承認（資料を AI に送るのは API と同じ）、(2) 見本での品質の比較（P-G5）の合格が必要。

## 仕組み
- `ai.provider: claude_code_queue`（`ai.queue_dir`、既定 `work/queue`）にすると、AI への依頼は `queue/requests/<id>.json` に書き出される
  （id は依頼の内容の指紋。同じ依頼は同じ id、答えは使い回す）
- 答えの無い依頼は「回答待ち」（失敗ではない）として、状態を変えずにその実行を止める。同じコマンドを繰り返すと答えた分だけ進む
- 答えは `structlab queue answer` が出力の形（JSON スキーマ）で検査してから保存する。形に合わない答えは保存しない
- 読み取り: `python3 scripts/queue_reading.py <無料の前処理の成果物>... --work work/g5`（Dropbox に触れない）
- 理解・統合: `python3 -m structlab.reading.semantic_bridge work/g5 --out work/g5/corpus/semantic_run -c <G5 の設定> --allow-external-ai`

## 答え方（Claude Code のエージェント 1 件 1 件。品質を API と同じにするための決まり）
1. 1 件ごとに新しいエージェント（前の依頼の内容を持ち込まない）。モデルは claude-opus-5-5、effort は API と同じ high
2. `python3 -m structlab queue show <id>` で指示（system）・画像の一覧・本文・出力の形を表示する
3. 画像は一覧の順にすべて Read で開く（縮小した写しを作らない）。指示（system）を指示として、本文を資料として扱う
4. 出力の形に合う JSON だけを作り、ファイルに書いて `python3 -m structlab queue answer <id> <ファイル>`。形が合わなければ直して再度
5. 推測で埋めない（読めない部分は出力の形にある「読めない」欄に書く）。API の指示文と同じく、通知・個人の情報は書き起こさない

## 費用と時間（全 9 資料の見込み）
| 項目 | 量 |
|---|---|
| 依頼の数 | 読み取り 約 630 件＋理解・統合 約 890 件 |
| 入力・出力 | 入力 約 3,400 万トークン（画像を含む）、出力 約 470 万トークン＋エージェントの指示文の繰り返し |
| 支払い | API 0 円（定額の契約の利用枠を使う。**追加利用（overage）を有効にしていると超過分が課金されるので無効または上限を設定**） |
| 時間 | 数十時間〜数日（利用枠の 5 時間ごとの上限で待つことがある）。時間が長いこと自体は費用にしない（M26） |

## 品質の比較（P-G5、承認待ち）
見本の資料（事前説明1）を API で 2 回（揺れの基準）と Claude Code で 1 回、読み取りから理解・統合まで行い、
`structlab pilot compare` の基準（包含率が同じ方式どうしの揺れ以内、重要項目の欠落が増えない）で比べる。API の費用 約 1,500 円（mid）。
不合格なら G5 は使わない（または不合格の工程だけ API に戻す）。

- Claude Code の会話の指示文・道具の出力が加わることによる答えの違い。比較で確かめる
