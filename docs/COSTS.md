# 費用の構造と最適化

成果物と品質を変えないことを絶対条件に、費用を工程ごとに測り、**内容が同じと確かめられた削減だけを採用**する。
品質の同等性をまだ確かめていない削減は「候補」として既定で無効にし、見本での比較（`structlab pilot`）に
通ったものだけを有効にする。有料AIの実行（本番・見本とも）は予算の承認後に限る。
M24・M25 の調査・方針・検証の記録は `docs/OPTIMIZATION_M24.md`・`docs/OPTIMIZATION_M25.md`、最適化の前後の保存データは `snapshots/`。

## 費用の測り方

| 何を | どこで | 備考 |
|---|---|---|
| 読み取りの依頼の数・入力トークン | `token_counts.json`・`summary_all.md`（`read --count-tokens`、無料の `count_tokens` API） | 入力は実測。見積もりの式（画像は公式の ⌈幅/28⌉×⌈高さ/28⌉）と実測の差は ±0.3%。出力は仮定 |
| 意味理解の依頼の数・入力 | `corpus/semantic_run/semantic_estimate.json` | 場面の数・文字数は実測 |
| 工程ごと・最適化ごとの円 | `corpus/costs/costs.json`（`structlab cost`） | low / mid / high の仮定は `costmodel.ASSUME`。M24 より前の構成との比較も出す |
| GitHub Actions の利用時間 | `corpus/costs/actions_usage.json`（`scripts/actions_usage.py`） | ジョブごとに分単位で切り上げ。非公開リポジトリは月の無料枠から差し引き |
| 実際の課金（有料実行のとき） | 各 AI 結果の `input_tokens`・`output_tokens`・`cache_read_tokens`・`cache_write_tokens` | キャッシュの当たり方を実測できる |
| 最適化作業そのもの | 見本の比較の追加費用を `structlab pilot plan --semantic-db ...` に表示 | 承認後に実行 |

## 採用済み（内容が同じことを確認済み）

| 最適化 | 内容が同じと言える理由 | 効果 |
|---|---|---|
| Batch API | 同じ依頼・同じモデルで、届くのが遅いだけ | 入出力とも半額 |
| 依頼をまとめて送る（M24） | 指示の抽出・照合は互いの結果を使わないので、資料ごとに 1 回の Batch で送る。依頼の全文と結果が 1 件ずつの場合と同じことをテストと独立した検証で確認 | Batch を待つ回数が減る。同じ先頭部分が同じ Batch に入りキャッシュが効く |
| キャッシュの先書き（M24） | 公式の推奨手順。キャッシュは応答を変えない（公式）。依頼の中身はキャッシュの設定以外同じ（テスト） | 同じ先頭部分の依頼が 6 件以上のとき、先頭部分の入力が約 1/7 |
| 中断した Batch の再開（M24） | 送信した Batch の ID を依頼の指紋と保存し、同じ依頼の集まりなら結果を取りに行く | 中断後の二重払いを防ぐ |
| 実験区間・参照画像・指示文のキャッシュ | 送る内容・順序は同じ | — |
| 依頼の指紋（`request_hash`）による再利用 | 依頼の内容が完全に同じときだけ、保存した結果を使う | 再実行・中断後の再開で二重に払わない |
| 意味理解の DB を Actions のキャッシュに保存 | 読み取り結果の指紋（`reading_fingerprint`）が同じ資料だけ再利用 | 再実行時の意味理解の再送をなくす |
| 役割ごとのキャッシュ鍵（`role_key`） | 設定を変えた役割の資料だけ読み直す | 無料の前処理の時間と、変わっていない資料の AI 費用 |

## 候補（品質の比較が必要。既定は無効）

| ID | 内容 | 見込める削減（mid、本番 1 回） | 比較の追加費用（段階を分けた比較） |
|---|---|---|---|
| C1v+C4 | 照合で指示文と資料全体の理解を画像の前に置いてキャッシュ＋同じ場面の照合を最大 5 件まとめる | 約 1,820 円（9 資料） | 約 516 円（照合の段階だけを見本の資料で比べる。**推奨**） |
| C1r | 再解釈で資料全体の理解を先頭に（1 時間のキャッシュ） | 約 730 円 | 約 1,230 円 → 本番 1 回では元が取れない |
| D1 | Excel の細部の読み取りで「変化した画面の全体」を 2 倍ではなく元の解像度に（変わった部分の 3 倍の拡大は残す） | 約 775 円 [推定] | 約 500 円 [推定]。M21（最高品質）の指示があるため利用者の判断待ち |
| C5（M25） | 再解釈で変わった項目だけ返させる（今は変更がなくても解釈の全体を書き直させている） | 約 510 円（C1r と合わせて 約 1,250 円） | C1+C4+C5 をまとめて再解釈から先を比べると 約 1,036 円で削減 約 3,065 円（**推奨**） |
| C2 | 意味理解の材料の短い書き方 | 約 110 円 | 約 2,080 円 → 比較しない |
| C3 | （逆方向）実験区間を 4 つまとめて読む今の構成と区間ごとの同等性 | 同等でなければ費用は増える | 指示 P085 の矛盾の解消のため |

採用の条件（`structlab pilot compare`）: 今の方式をもう一度実行したもの（repeat）を揺れの基準にし、
候補の包含率 ≥ repeat の包含率 − 0.02、かつ重要項目（禁止・必須・条件付きの指示、数値、セル番地、数式、設定、照合の判定）の
欠落が repeat 以下のときだけ採用する。満たさなければ今の方式のまま。

## 採用しなかったもの

| 案 | 理由 |
|---|---|
| モデルの格下げ・段階的な切り替え・effort を下げる | 指示（M16・M23・M24）で禁止／理解の深さが下がる |
| 実験区間を 15 秒あたり 2 枚に・画面の縮小 | M20・M21 の指示に反する。細部（セル・数式・ひび割れ）を落とす |
| 照合・再解釈の回数を減らす | 出力（照合の結果）が減る |
| 資料全体の発話を共通の先頭に置き、場面ごとの材料を省く | 削減（数百円）に比べて材料の与え方の変更が大きく、比較の費用が見合わない |
| キャッシュを常に 1 時間 | 使い直さない依頼では書き込みが 2 倍になり高い（先書きの対象だけ 1 時間） |

## 未検証の項目
- 出力の量（AI が書く量・思考の量）は実測できないので幅で示す（low / mid / high）
- Batch の中・先書き後のキャッシュの当たる割合は公式に保証されない（仮定は `costmodel.ASSUME`）。有料実行で `cache_read_tokens` を実測できる
- P085（実験区間をまとめて読む構成と区間ごとの同等性）は C3 の見本で確かめるまで未解決
