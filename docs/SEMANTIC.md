# 意味理解層（局所理解・全体理解・指示の網羅的抽出と照合）

文字起こし・OCR・画像説明の「抽出」だけでなく、先生が何を、なぜ説明し、資料全体で何を伝え、
学生に何をしてほしいのか・してはいけないのかを、根拠（資料名・時刻・ページ・発言・画面）付きで理解するための層です。
既存の抽出結果（動画の区間・時刻同期した発話と画面・PDFのページ・Excelのシート範囲など）をそのまま「場面」として使います。

実装: `src/structlab/semantic/`（`engine.py` 段階の実行、`rules.py` 言い回しの規則、`relations.py` 関連付け、
`corpus.py` 資料横断、`report.py` 出力・網羅率・検索、`estimate.py` 費用の概算、`prompts.py` AIへの指示と出力スキーマ）

## 1. 2つのモード

| モード | いつ動くか | 内容 |
|---|---|---|
| **local**（規則のみ） | 常に（`semantic.enabled: true`） | 言い回しによる指示の抽出と8分類、条件、訂正・補足・例外・条件変更の標識、関連付け、矛盾候補、網羅率。**意味の理解はしない** |
| **ai**（意味理解） | `semantic.ai: true` **かつ** 外部送信の明示的な許可（`--allow-external-ai`）があるときだけ | 下記の3段階。local の結果は「見落とし検査」「分類の向き・強さの検査」に使う |

AI が無い・許可されていない場合、「AIによる全体理解は未生成」と明示し、規則の結果を意味理解の結果のように見せません。

## 2. ai モードの3段階

**第1回: 内容と意味の理解**
1. 場面ごとの局所理解: 時刻同期した発話・画面（キーフレーム画像）・OCR・重要場面の高解像度フレームに、
   直前の場面の理解と直後の場面の発話を添えて、9項目（話している内容・画面・操作・意味・目的・前後との関係・対象者・作業・提出物）と
   訂正/補足/例外/条件変更/強調、不確かな点、読み取れない点を記録
2. 資料全体の理解: 全場面の理解から、テーマ・目的・流れ・論理構造・各場面の役割・手順と依存関係・結論・重要事項・
   訂正等・繰り返された注意・一見矛盾する説明の整合性・最終要件・理解してほしいこと・実行してほしいこと・詳しい説明
3. 相互照合: 全体理解を渡して各場面を再解釈 → 変更があれば全体理解を更新 → 変更がなくなるまで（上限 `max_rounds`）。
   各回の解釈と変更点（変更前・変更後・理由）は版として保存。上限に達しても変更が残れば「収束せず（要確認）」と記録

**第2回: 指示の重点抽出**
- 全体理解・場面の理解・前後の場面・元の発話を渡し、A〜H の8分類で1件ずつ抽出（条件・強さ・対象作業・提出物・根拠の原文・前後・確実性・明示/推論・訂正等の関係）
- 規則で拾った候補を番号付きで全件渡し、採用（一致）か「指示ではない」（理由付き）かを答えさせる。どちらでもない候補は**見落とし候補**になる

**第3回: 元資料との照合**
- 機械照合: 根拠の引用が元の発話・画面・資料の該当時刻付近にあるか、分類が原文の言い回しと**向き**（してよい/いけない）・**強さ**で矛盾しないか、時刻・条件の欠落
- 問題のある指示と見落とし候補は、前後 `verify_expand_seconds` 秒に広げて再解析（元動画が手元にあれば画面を取り直し、区間の境目をまたいで音声を再文字起こし）
- 判定: 確認済み／修正（修正案も原文の言い回しと矛盾しないか再検査。矛盾すれば採用せず「分類の食い違い（未解決）」）／指示ではない／判断不能（要確認）
- 上限（`max_verify_per_doc`）を超えた分は「要確認」として残す

**関連付け**（両モード）
- 訂正: 原文に訂正の言い回し（「訂正します」「さっき〜と言いましたが」等）がある場合だけ、前の指示を「訂正により無効」にする。AIの判断だけの訂正は候補として残し、前の指示は無効にしない
- 例外・補足・条件変更: 対象が似た前の指示に関連付け。見つからなければ直前の指示に対するものと推定（要確認）
- 向きが逆で対象が似た指示（例: 「触らないで」⇔「触ってもよい」）や値の違い（PDF⇔Word）は**未解決の矛盾**として記録し、どちらが正しいかは決めない
- 同じ指示の繰り返し・複数資料に共通する指示を関連付け

**資料横断の統合**（全資料の意味理解が終わった後、1回）
- 各資料の全体理解と指示一覧（#番号）から、実験全体の目的・内容・手順・データ処理・Excel作成方法・レポート作成方法・作業順序・依存関係・提出物と要件・共通指示・補足・訂正・矛盾
- 資料単位の理解（`scope=document`）とは別に保存（`scope=corpus`）。AIが存在しない指示番号を挙げた場合は除外し、その事実を記録

## 3. 指示の分類と記録項目

分類: A 禁止 / B 非推奨 / C 必須 / D 要望 / E 推奨 / F 任意 / G 条件付き（条件内の強さを別に記録） / H その他・判断不能

各指示の記録（`directives.json`）: 内容、分類、条件内の強さ、対象作業、提出物、対象者、条件、資料名、開始・終了時刻（またはページ）、
関連する画面（キーフレーム・画面の文字）、操作、根拠の発言（原文）、前後の文脈、確実性、未確認事項、明示かAIの推論か、
抽出方法（規則／AI／規則＋照合）、言い回しの手掛かり、照合状態と照合メモ、有効性（有効／訂正により無効／未解決の矛盾 等）、関連する他の指示（訂正・補足・例外・条件変更・矛盾・同一）

|---|---|---|
| 1 | `scenes/*.md, *.json` | 場面ごとの意味解析（最終版と再解釈の変更履歴、元の発話・画面） |

## 5. 網羅率について

`coverage.md` の網羅率は「動画の時間（資料の単位数）のうち、各段階の処理が完了した割合」です（文字起こし・画面取得・規則抽出・局所理解・再解釈・指示抽出・照合ごと）。
未処理の時間帯も列挙します。**これは「すべての指示を理解できた割合」ではありません。**
指示の検出率は正解データが無いため算出せず、代わりに見落とし候補の数・照合状況を示します。

## 6. 有料APIの承認手順

1. AIなしで `scripts/run_analysis.sh`（抽出と規則のみ。無料）
2. 表示される概算（`structlab estimate`）で呼び出し回数・トークン数・費用の範囲を確認
3. 承認したら `scripts/run_analysis.sh --allow-external-ai`
4. 1回の実行の上限（`ai.max_calls_per_run` 等）に達したら残りは次回に持ち越し。完了済みの段階はやり直しません
