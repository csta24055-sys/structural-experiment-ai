# G5 の作業フォルダの保全（M28）

台帳 P153・P154。実装は `scripts/g5_backup.py`、試験は `tests/test_backup.py`。

## 1. 何が失われるか
作業環境（クラウドのコンテナ）は、長く操作が無いと回収され、`work/` は残らない [公式]。再起動では残った [実測、M27]。

| 作業フォルダの中身 | 作り直せるか | 保存の対象 |
|---|---|---|
| 依頼・依頼の画像（約 3 GB） | 作れる（前処理の成果物から同じ依頼・同じ番号。無料の計算 約 1.5 時間） | しない |
| **答え**（`queue/answers/`、資料の内容を含む） | 作れない（答え直すと利用枠と時間を使う） | **する** |
| **P-G5 の結果**（`pg5/`、API の答えは有料） | 作れない（作り直すと約 1,000 円） | **する** |
| テスト用の印（`TEST_ONLY_DO_NOT_USE`） | — | する（仮の答えのフォルダを本番に使わないため） |
| 進捗（`g5_status.json`） | 作れる | する（小さい） |

前処理の成果物（v7、GitHub Actions の保存物）は 2026-11-20 まで保存。それ以降は前処理のやり直し（Actions の無料枠）が必要。

## 2. 保存先の比較
| 方法 | 費用 | 安全性 | 容量 | 復旧の確実性 | 判断 |
|---|---|---|---|---|---|
| **Dropbox の解析結果フォルダ（スクリプトが API で直接書く）** | 0 円 | 元資料と同じ利用者本人の保存領域。公開しない。元資料のフォルダの外に**追加だけ**（同じ名前があれば失敗。上書き・削除しない） | 答え 約 1,500 件で 約 5〜15 MB（圧縮で 数 MB）[推定。仮の答え 1,150 件で 4.6 MB を実測] | 高い（作業環境と無関係に残る。中身の sha256 で壊れを検出） | **採用** |
| Dropbox（会話の中の Dropbox コネクタで書く） | 0 円 | 同上 | 1 ファイル 5 MB まで、文字だけ | 中（保存の内容が会話を通るので利用枠を使う。書き込みのたびに利用者の確認が必要） | 予備（認証情報を環境に登録できない場合だけ） |
| GitHub のリポジトリ（コミット） | 0 円 | 不可: 解析結果のコミットは禁止（P093）。履歴に永久に残る | — | — | 不採用 |
| GitHub に暗号化して置く（ブランチ・リリース） | 0 円 | 暗号文でも解析結果を GitHub に置くことになり、鍵の保管場所が別に必要（鍵を失うと戻せない） | — | 鍵の管理しだい | 不採用 |
| GitHub Actions の保存物・キャッシュ | 0 円 | データを Actions に渡すにはコミットが必要（不可） | 保存は最長 90 日 | — | 不採用 |
| その他のクラウド（S3・Google Drive 等） | 0〜数十円 | 新しいアカウント・鍵・個人データの置き場所が増える | 十分 | 高い | 不採用（増やす理由がない） |
| 保存しない（消えたら答え直す） | 0 円 | — | — | 時間と利用枠を失う | 予備 |

## 3. 仕組み
- 束: `g5-<通し番号>-<内容の sha256 先頭 12 桁>.tar.xz`（中に `manifest.json`: ファイルごとの sha256）。前回から増えた・変わったものだけを束ねる
- 保存先: `/鋼材実験レポート用_解析結果/g5_backup/`（元資料のフォルダ `/鋼材実験レポート用` と重なる場所は拒否）。
  Dropbox の書き込みの方式は `add`・名前の自動変更なし（同じ名前があれば失敗）。上書き・削除の処理は無い
- 自動: 環境変数 `G5_BACKUP=dropbox` があれば、`g5_driver.py step` が答えの取り込みの直後に保存する。失敗は止めずに
  `g5_status.json` の `backup.error` に記録（認証情報の値は出さない）→ 進行役が止めて利用者に知らせる
- 復元: `python3 scripts/g5_backup.py restore`。名前と中身の sha256 を確かめ、壊れた束は使わない。手元に既にあるファイルは上書きせず
  「conflicts」として報告。戻した答えは、作り直した同じ依頼（同じ番号）にそのまま使われ、答え直しは 0 件

## 4. 試験（無料）
- `tests/test_backup.py`: 増えた分だけの保存、作業フォルダを消して復元 → 依頼を作り直すと答え直し 0 件、保存先は追加だけ、
  手元の別の版を上書きしない、書き換えた束を使わない、テスト用の印が復元後も残る、Dropbox の書き込みが add・元資料の外、
  step からの自動保存と失敗の記録
- 実地の試験: 全 9 資料の試験用フォルダ（仮の答え 1,150 件）を保存 → 新しいフォルダに前処理の成果物から作り直し → 復元 → 完走するか
  （結果は M28 の報告）
- Dropbox への実際の書き込みは未実施（利用者の確認の後。認証情報も未登録）

## 5. 有効にするために残っていること（利用者の判断が必要）
現在の Dropbox のトークンは**読み取り専用**（docs/SETUP_DROPBOX.md: scope は files.metadata.read・files.content.read）で、
しかも GitHub Secrets の中にしかなく、この作業環境からは使えない（Secrets は Actions からしか読めない）。保存を有効にするには、
書き込みの許可のあるリフレッシュトークンを、作業環境の設定（環境変数）に置く必要がある。

| 渡し方 | 利用者の操作 | トークンの値が見える場所 | 判断 |
|---|---|---|---|
| A. 暗号化して受け渡す（推奨） | (1) App Console で files.content.write を追加 (2) 自分で決めた長い合言葉を GitHub Secret `G5_HANDOFF_KEY` と環境変数 `G5_HANDOFF_KEY` に登録 (3) 既存の手順（dropbox-auth の preflight → 許可 → exchange）で書き込みの許可つきのトークンを作る | どこにも平文で出ない（Actions が合言葉で暗号化して Dropbox の解析結果フォルダに置き、作業環境が合言葉で復号して使う） | 未実装（承認後に実装。Actions の変更と Dropbox への書き込みを伴う） |
| B. 利用者が値を写す | (1)(3) は A と同じ。Actions がトークンを利用者の Dropbox のファイルに書き、利用者が環境変数に写してファイルを消す | 利用者の Dropbox に一時的に平文で置かれる | 推奨しない |
| C. 有効にしない | なし | — | 消えたら答え直す（支払い 0、時間と利用枠を使う） |

いずれも Dropbox への書き込みは元資料のフォルダの外・追加だけ。書き込みを始める前に利用者の確認を得る（台帳 P090 との関係は P153 の conflicts）。
認可コードは数分で失効するため、コードを環境変数に置いて新しいセッションで交換する方式は使えない。
