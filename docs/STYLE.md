# 本人の文章スタイル（最終工程だけに使う）

本人の文章の特徴を整理したPDF（部・節・番号付き項目の構成）を読み込み、
**内容・構成・計算・考察が確定した後の文章表現の調整**にだけ使います。実装: `src/structlab/style/`

## 使わないところ
資料の意味理解、教授の指示の判断、数値計算、Excelの作成、実験結果の評価には使いません。
解析・チェックのコードからはこのモジュールを参照していないことを、自動テストで確認しています。

## PDFの置き場所（リポジトリには置かない）
PDFは個人情報を含むため GitHub に保存しません（`.gitignore` 済み）。次のどちらかで指定します。
- `style.dropbox_path`: Dropbox 上のパス（**解析対象フォルダの外**。例: `/鋼材実験レポート用_解析結果/style/writing_style.pdf`）
- `style.pdf_path`: 実行環境のローカルパス

読み込んだ結果は `work/style/profile.json`（作業ディレクトリ・コミットされない）に保存します。
PDFが無い・`style.enabled: false` の場合は、文章を変えずにそのまま返し、ほかの処理は止まりません。

## 全項目を機械的に適用しない
読み込んだ項目を「適用してよい／除外」に分け、理由とともに `profile.json` に残します。既定の方針:
- 第1部（入力・会話の基礎的な特徴）は、正式なレポートの正確性を損なうおそれがあるため使わない。他の部でも、誤字・脱字・句読点の省略など正確性を損なう項目は除外
- 就職活動の文書（ES・志望動機・自己PR）向けの節・項目は、実験レポートに当てはまらないため使わない
- 適用に使うのは最大 `style.max_rules` 項目（既定120）。最終チェック用の部（第4部）を優先し、節ごとに順に選ぶ

## 適用と再検証
1. 適用前の文章を必ず保存（`style_runs`、CLI では `*.original.md` も出力）
2. AI に「表現だけを調整。数値・数式・結果・根拠・引用・教授の指示・論理構造・結論・主張の強さを変えない。経験していないこと・考えていないことを書き足さない」と指示（`--allow-external-ai` のときだけ・有料）
3. 適用後に機械的に再検証:
   - 不一致（採用しない）: 数値・単位、数式、引用（「」内）が変わった
   - 要確認（既定では採用しない）: 否定表現の数、断定・推測の強さ、結論の文、元に無い語の増加（書き足しの疑い）、消えた語、文の数の大きな変化
4. 不採用の場合は元の文章を最終版とし、調整案と検査結果は記録に残す
5. 表・数式ブロックを含む節は調整しない

## コマンド

```bash
structlab style profile                  # PDFを読み込み、項目数・除外数を表示
structlab style status
structlab style apply 確定稿.md --out 調整後.md --allow-external-ai
```

## 確認状況
- 実物のPDFの読み取り: 全項目を読み取り、PDF内に書かれた各節の項目数の合計と一致することを確認（このセッションのみ。PDFと読み取り結果・その内容はコミットしていない）
- 適用の質（本人らしくなるか）は、実際のAIと確定した文章が無いため未検証
