## 1. 公式の利用条件との関係（2026-10-22 確認）
| 確認したこと | 公式の記述 | 判断 |
|---|---|---|
| 定額の契約で Claude Code を使えるか | Pro・Max の Claude Code は消費者向けの規約。「Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK」 https://code.claude.com/docs/en/legal-and-compliance | 利用者本人が、本人の Claude Code で、本人の資料を処理するのは想定内 |
| 禁止されていること | 第三者の製品が claude.ai のログインで他人の依頼を流すこと、アカウントの共有・転売、保護の仕組みの回避（https://www.anthropic.com/legal/consumer-terms 第 3 条）。API キー以外の自動の手段は「明示的に許可された場合」を除き不可 | G5 は外部のプログラムから Claude を呼ばない。AI は利用者が始めた Claude Code の会話とそのサブエージェントだけ（公式の機能）。実行役のスクリプトは AI を呼ばない |
| 自動化の許可 | `claude -p`・Agent SDK も定額の利用枠で使える（https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan）。サブエージェント・ワークフローも利用枠を使う（https://code.claude.com/docs/en/sub-agents.md） | G5 は会話の中のサブエージェントだけを使う（最も明確に「アプリそのもの」の使い方） |
| 利用枠 | 5 時間ごと・週ごとの上限。上限では「回復の時刻まで止まる」、モデルを変えても回復しない（https://code.claude.com/docs/en/errors.md）。大量の並列は週の上限を早く使い切る | 上限では止まって待つ（回避しない）。並列は 10 程度 |
| 追加の課金 | 追加利用（usage credits）は申し込み制。無効にでき、月の上限を設定できる（https://support.claude.com/en/articles/12429409） | 開始前に無効または上限を設定してもらう。毎周 isUsingOverage を確認し、true なら止める |
| モデルの切り替え | 利用の上限・請求では切り替えない。過負荷時の切り替えは `--fallback-model` を設定した場合だけ。例外: 内容の分類による切り替え（サイバー・生物の内容）。サブエージェントは固定しないと別のモデルになりうる（https://code.claude.com/docs/en/model-config.md） | 答え役の定義でモデルを claude-opus-5-5 に固定。答えごとにモデル名を記録 |
| クラウドの作業環境 | 定額の利用枠に含まれ、別の料金なし。操作が無いと止まる（https://code.claude.com/docs/en/claude-code-on-the-web.md） | 費用 0。ただし作業フォルダが消えるおそれ（§5） |
| 画像 | Read は大きな画像を縮小・再圧縮する（https://code.claude.com/docs/en/tools-reference.md）。合成画像で 2576×1449 → 2000×1125 を確認 [実測] | 長辺 2000 を超える画像は元の画素の部分画像を添える |
| 未確認 | 「通常の個人の利用」の量の閾値は公式に無い | 判断は Anthropic にある。利用者の指示で、利用者の資料を、1 つの会話で処理する範囲にとどめる |

## 2. API と G5 の入出力の同等性
| 項目 | API | G5 | 対応 | 状態 |
|---|---|---|---|---|
| モデル | claude-opus-5-5、effort high、思考は自動 | 同じモデルに固定（答え役の定義）、effort high | 定義で固定・答えに記録 | 合成の試験で claude-opus-5-5 を確認 [実測]。内容の分類による切り替えの有無は答えごとの記録で見る |
| 指示文 | 依頼の system だけ | Claude Code の指示文＋答え役の定義＋依頼の system（文書として） | 依頼の内容は同じ。差は避けられない | **P-G5 で確認** |
| 画像 | 長辺 2576 まで、WebP 可逆（大きすぎるときは JPEG q97） | API と同じ符号化をして戻した画素の PNG ＋ 長辺 2000 超は元の画素の部分画像 | 画素の情報は同じ以上 | 合成画像の 7 px の数字まで 72/72 正しく読めた [実測]。実際の資料は **P-G5** |
| PDF・音声・動画由来の情報 | 依頼の本文に入る | 同じ本文（依頼の指紋で同一を確認） | — | 同一 [テスト] |
| 文脈の長さ・省略 | 1 依頼 | 1 依頼＝新しい答え役 1 体。本文は行に分けた Markdown、全体の行数と終わりの印で読み落としを検出 | 長い 1 行の切れを防止 | [テスト] |
| 出力の形 | JSON スキーマで強制 | 取り込み時に同じスキーマで検査、合わなければ却下して答え直し | 同じ構造 | [テスト] |
| 会話履歴・作業環境 | なし | 1 件ごとに新しい答え役。道具は Read と Write だけ。依頼と画像以外は開かない決まり | 混入を防止 | 定義・[合成の試験] |
| 長時間の欠落 | — | 状態はすべてファイル。進行役の会話が長くなっても依頼・答えはファイルから | — | [テスト] |
| エラー・中断・再開 | Batch の再開 | 回答待ちは失敗にしない、受け渡し中の印（2 時間）、書きかけを残さない置き換え、壊れた・重複・依頼と合わない答えの検出 | — | 異常系のテスト 7 種 [テスト] |

## 5. 現実の制限
- 依頼 約 1,500 件、理解・統合は最も長い資料で 約 100 周。利用枠の回復待ちを含め数十時間〜数日。利用者の操作は上限で止まったときの「続けて」
- **作業フォルダの消失**: クラウドの作業環境は操作が無いと止まり、作業フォルダ（`work/`）は残らない [公式]。答えは資料の内容を含むため、
  GitHub（コミット禁止）にも Dropbox（書き込みしない指示）にも置けない。消えた場合は v7 の成果物（2026-11-20 まで保存）から依頼を作り直し、
  失った答えを答え直す（支払いは 0、時間と利用枠を使う）。保存先を許可いただければ（例: Dropbox の解析結果フォルダ）防げる
- 週の上限に達すると数日止まる

## 6. P-G5（有料の比較、承認待ち）
- 比較対象: G5 の受け渡し口に作った依頼から種類ごとに選んだ 30 件（読み取り 6 種 18 件・理解統合 5 種 14 件のうち実在する分）。
  同じ依頼を API で 2 回（Batch）と G5 で 1 回。理解・統合の依頼は G5 の読み取りの答えから作られた同じ依頼を使う（依頼ごとの比較）
- 判定（種類ごと）: 包含率が API どうし − 0.02 以上、重要項目（数値・セル番地・数式・設定・禁止/必須/条件付きの指示・照合の判定）の欠落が API どうし以下、
  「読めない・不確か」が API の 1.25 倍＋1 以下。全種類が合格で G5 を採用。不合格の種類は API に戻す（組み合わせ C）
- 費用: 約 790 円（API 2 回分）。より安い案（API 1 回＋G5 2 回、約 400 円）は G5 の揺れを基準にすると判定が甘くなりうるので推奨しない
- 手順: `python3 scripts/g5_driver.py step` を読み取り・理解統合の見本が出そろうまで進める → `python3 scripts/pg5.py select` →
  （API の鍵を環境に登録した新しいセッションで）`python3 scripts/pg5.py run-api --allow-external-ai` → `python3 scripts/pg5.py compare`
